# 本轮安全优化说明

本轮优化针对模拟和研究版本，目标是让批量做市计划更稳定、更容易解释，同时保持真实下单默认关闭。

## 已完成

### 1. 行情快照质量门禁

新增 `validate_snapshot()`，在生成报价之前检查：

- 中间价、买一、卖一是否为有限正数；
- 买卖盘是否交叉；
- 深度、成交额和波动率是否为负数；
- 是否存在非数值行情。

异常行情会进入 `pause`，不会生成报价意图。

### 2. 风险参数真正传入批量计划

`plan_batch(..., daily_pnl=...)` 现在会把当日盈亏传给风险检查。达到日亏损上限后，计划会明确包含 `daily_loss_limit` 阻塞原因。

### 3. 全局拦截后的统计保持一致

此前全局名义仓位或订单数超限时，订单已经被清空，但返回的订单统计仍然显示拦截前的数量，容易造成误判。

现在 `BatchPlan` 区分：

- `requested_*`：拦截前计划请求的数量；
- `gross_notional`、`net_notional`、`total_orders`：最终可执行数量；
- `blockers`：具体的全局阻塞原因。

如果触发全局上限，最终可执行数量为零，并保留原始请求统计供分析。

### 4. 库存减仓阈值统一

Hedge Mode 的减仓阈值现在取配置净仓位上限与风险库存上限中的较小值，避免订单逻辑使用了比风险模块更宽的阈值。

### 5. 配置启动校验

`MakerConfig` 会拒绝无效的订单名义价值、tick size、订单层数和负数限制，减少配置错误导致的异常计划。

### 6. 报价安全检查

报价经过 tick size 舍入后，如果出现非正价格或买价大于等于卖价，会直接暂停并返回 `invalid_rounded_quote`。

## 尚未实现

本项目仍然是 simulation/research 版本，以下内容没有接入：

- 真实交易所下单；
- 多账户自成交或批量刷量；
- 用户数据流对账；
- 实盘撤单、部分成交和断线恢复；
- 真实返佣到账验证。

`makerlab/live.py` 继续默认阻断真实提交。任何生产接入都必须先完成交易所规则校验、权限审计、风控和合规评估。
